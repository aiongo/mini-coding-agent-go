# Interactive Example

**English** | [简体中文](EXAMPLE.zh-CN.md)

This is a hands-on example workflow for using `mini-coding-agent-go` with Ollama on small Python projects.

Two walkthroughs are included:

- **Example 1** implements, edits, and tests a binary search function.
- **Example 2** builds a benchmark app that compares two sort algorithms on a real data file.

These examples assume:

- `ollama serve` is already running
- the default model `gemma4:cloud` is available in your Ollama instance
  (e.g., via `ollama pull gemma4:cloud`)
- you already cloned `aiongo/mini-coding-agent-go`
- you already ran `go build` in your local `mini-coding-agent-go` folder

&nbsp;
## Example 1: Implement Binary Search

The flow is:

1. create a fresh repo
2. launch the agent
3. implement `binary_search.py`
4. edit the implementation
5. add `pytest` tests
6. run tests
7. fix anything that fails

&nbsp;
### 1. Create a fresh repo

```bash
cd mini-coding-agent-go
mkdir -p ./tmp/binary-search-repo
cd ./tmp/binary-search-repo
git init
```

At this point the repo is basically empty:

```bash
ls -la
```

&nbsp;
### 2. Launch the agent

Open the agent from your `mini-coding-agent-go` clone, but point it at the new repo:

```bash
cd mini-coding-agent-go
./mini-coding-agent-go --cwd ./tmp/binary-search-repo
```

It runs with the default model, `gemma4:cloud`.

(The screenshots below are from the Python original; the Go REPL uses the same
`mini-coding-agent>` prompt and the same flow.)

For a single prompt without the REPL, use the `prompt` subcommand (alias `p`):

```bash
./mini-coding-agent-go --cwd ./tmp/binary-search-repo \
  prompt "Inspect this repo and summarize the layout"
```

<img src="https://sebastianraschka.com/images/github/mini-coding-agent/1.webp" width="500px">



&nbsp;

### 3. Ask it to implement binary search

At the `mini-coding-agent>` prompt, paste:

```text
  Inspect this repository and create a minimal binary_search.py file. Implement an iterative binary_search(nums, target) function for a sorted list of integers. Return the index if the target exists and -1 if it does not. Keep the code very small.
```

After the agent finishes, inspect the result in another terminal or code editor. The contents are shown below:

<img src="https://sebastianraschka.com/images/github/mini-coding-agent/2.webp" width="200px">

&nbsp;
### 4. Ask it to edit the implementation

Now make a small follow-up change. Back in the agent REPL, paste:

```text
Update binary_search.py so it raises ValueError if the input list is not sorted in ascending order. Keep the implementation simple.
```

Check the file again:

<img src="https://sebastianraschka.com/images/github/mini-coding-agent/3.webp" width="300px">

&nbsp;
### 5. Ask it to add unit tests

Back in the REPL, paste:

```text
Create test_binary_search.py with pytest tests for found, missing, empty list, first element, last element, and unsorted input raising ValueError. Keep the tests small and readable.
```

Inspect the new test file:

<img src="https://sebastianraschka.com/images/github/mini-coding-agent/4.webp" width="250px">

&nbsp;
### 6. Ask it to run the tests

Back in the REPL, paste:

```text
Run pytest for this repo. If any test fails, fix the code or tests and rerun until everything passes.
```

You can also verify manually in a different terminal window:

```
python -m pytest tmp/binary-search-repo
```

&nbsp;
### 7. Inspect the final repo state

Check what changed:

```bash
cd mini-coding-agent-go
cd ./tmp/binary-search-repo
git status --short
```

You should now have:

- `README.md`
- `binary_search.py`
- `test_binary_search.py`

## Example 2: Compare Sort Algorithms on Real Data

This walkthrough builds a small benchmark app: it reads integers from a data file, runs
two sort algorithms several times, and reports per-run timings plus a correctness diff
between the algorithms. It exercises multi-step task prompts and the `run_shell` tool,
and benefits from a stronger model than Example 1.

&nbsp;
### 1. Create a fresh repo and copy the data files

The integers this example sorts are not generated by the agent — copy them from the
`data/` directory of this repository into the target repo:

```bash
cd mini-coding-agent-go
mkdir -p ./tmp/sort-benchmark-repo
cd ./tmp/sort-benchmark-repo
git init
cp ../../data/data.txt ../../data/data_lite.txt .
```

Two files are copied:

- `data.txt` — 100,000 signed integers, one per line (duplicates allowed)
- `data_lite.txt` — 2,000 signed integers, the reduced set for this example

Why two files: bubble sort is O(n²), which is not feasible on the full `data.txt` —
sorting 100,000 integers with bubble sort takes on the order of 10 billion comparisons,
far too long to finish inside the agent's step budget. `data_lite.txt` is provided for
this example so the bubble-sort comparison completes quickly. If you only build the
quicksort version of the benchmark, the full `data.txt` works fine.

&nbsp;
### 2. Launch the agent

A multi-step prompt like this one needs a model that follows instructions reliably, and
the benchmark repeats shell execution, so this example runs with `--approval auto` (still
on the default model, `gemma4:cloud`):

```bash
cd mini-coding-agent-go
./mini-coding-agent-go \
  --cwd ./tmp/sort-benchmark-repo \
  --approval auto
```

`--approval auto` is a convenience for benchmarking — remember it lets the model run
arbitrary commands and write files without asking.

&nbsp;
### 3. Ask it to build the benchmark

At the `mini-coding-agent>` prompt, paste (the REPL takes single-line input, so the
prompt is one paragraph):

```text
Create sort_algorithms.py that reads all integers (dups allowed) from data_lite.txt in the current dir, runs bubble sort and quicksort 5 times each, reports per-run times plus the average for each, then compares the last results of the two algorithms element-by-element and prints any differing indices along with the values at those indices.
```

(For a quicksort-only variant, point the prompt at the full `data.txt` instead.)

&nbsp;
### 4. Ask it to run the program

Once the file is generated, ask the agent to execute it from the REPL:

```text
help me execute this python program
```

The agent runs it through `run_shell` and the benchmark prints its report. Real output
from a run against `data_lite.txt`:

```text
Running Bubble Sort 5 times...
  Run 1: 0.077506s
  Run 2: 0.070776s
  Run 3: 0.069533s
  Run 4: 0.070005s
  Run 5: 0.070240s
Average Bubble Sort time: 0.071612s

Running Quicksort 5 times...
  Run 1: 0.001285s
  Run 2: 0.001218s
  Run 3: 0.001223s
  Run 4: 0.001182s
  Run 5: 0.001161s
Average Quicksort time: 0.001214s

Both algorithms produced identical results.
```

&nbsp;
### 5. Inspect the final repo state

Check what changed and rerun the benchmark manually:

```bash
cd mini-coding-agent-go
cd ./tmp/sort-benchmark-repo
git status --short
python sort_algorithms.py
```

You should see `sort_algorithms.py` alongside the two copied data files; the manual
rerun prints the same report.

## Useful interactive commands

While the agent is running, these commands are available:

- `/help` shows the available slash commands and what each one does.
- `/memory` prints the agent's distilled working memory for the current session.
- `/session` shows the path to the saved session JSON file on disk.
- `/reset` clears the current conversation history and working memory.
- `/exit` leaves the interactive agent.
